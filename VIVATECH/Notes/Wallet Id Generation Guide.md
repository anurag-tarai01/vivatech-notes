# Wallet ID Generation Guide

This document outlines the rules and configurations used by the MFS platform to generate unique Wallet IDs (also known as `tillNumber`s) for various user types during their creation and approval process.

## 1. What is a Till Number?

In this system, a **Till Number** acts as the base sequential account number or primary wallet ID for an entity.

The application utilizes a `TillNumberService` which queries the database to find the highest existing number that matches a specific **Prefix** and **Length** constraint. It then increments this number to guarantee that every new user receives the next logical, sequential number (e.g., `100000` followed by `100001`).

## 2. Global Configurations

The system relies on the following configurations (from `mfs-config.properties`) to determine the length and starting digits of the till numbers based on the user's role:

|User Type / Profile|Length|Prefix Config|
|---|---|---|
|**Customer Care**|6|`1` (Hardcoded in Saga)|
|**Agent (Default)**|6|`25` or `33`|
|**Agent (Gold)**|6|`21`|
|**Agent (Silver)**|6|`22`|
|**Agent (Bronze)**|6|`23`|
|**Merchant**|6|`44`|
|**Outlet**|6|`9`|
|**Subscriber**|8|`55` or `88`|

## 3. Actor-Specific Generation Rules & Examples

### Customer Care (Internal Admin)

- **Base Till Number Generation**: The system uses a fixed prefix of `1` and a length of `6`. It queries the database for the next sequential number.
- **Example Primary Wallet (`CUSTOMER_CARE`)**: `100000`, `100001`
- **Commission Wallet (`INTERNAL_AGENT_COMMISSION`)**: Generated by appending a single random digit (0-9) to the base till number.
- **Example Commission Wallet**: `1000001`, `1000019`

### External Agents

- **Base Till Number Generation**: The system determines the prefix based on the agent's assigned profile tier (Bronze=23, Silver=22, Gold=21). If no specific tier is assigned, it randomly selects from the default prefixes (`25` or `33`). The length is always `6`.
- **Example Primary Wallet (`AGENT`)**:
    - Gold Agent: `210000`
    - Silver Agent: `220000`
- **Commission Wallet (`AGENT_COMMISSION`)**: Just like Customer Care, a random digit (0-9) is appended to the base till number.
- **Example Commission Wallet**: `2100004`, `2200007`

### Subscribers

- **Base Till Number Generation**: The system uses a length of `8`. It randomly selects a prefix from the configured list (`55` or `88`).
- **Example Primary Wallet (`SUBSCRIBER`)**: `55000000`, `88000001`
- **Commission Wallet**: Subscribers do not receive commission wallets.

### Merchants & Outlets

- **Base Till Number Generation**: Follows the same sequential generation rules using their respective configurations.
- **Example Primary Wallet (`MERCHANT`)**: `440000` (Prefix 44, Length 6)
- **Example Primary Wallet (`OUTLET`)**: `900000` (Prefix 9, Length 6)

## 4. Special Mechanisms

NOTE

**Multiple Prefix Selection (e.g., `55;88`)**  
Configurations containing semicolons use the Spring Expression Language (SpEL) to split the string into a list of options (e.g., `[55, 88]`). During wallet generation, a random number generator picks an index from this list. This means every new subscriber has an equal 50/50 chance of being assigned the `55` or the `88` prefix.

TIP

**Commission Wallet Randomization**  
Commission wallets are **not** sequential. Because they append a `Random().nextInt(10)` to the base sequential till number, they will end with a randomized digit. This distinguishes the commission wallet from the main transactional wallet while keeping them logically grouped under the same base identifier.
